## Manual checks

- **Semantics:** every page exposes `main` + a single `h1`; footer is `contentinfo`; the chart is
  a `region` with an `h2`, the SVG carries the full plain-language summary as its accessible name,
  and a `<details>` table twin duplicates every value.
- **Keyboard:** logical tab order on the kiosk (focus lands on "Remembered" first); visible focus
  outline confirmed via computed style (`outlineStyle`/`outlineWidth`); screen transitions move
  focus to the new `h1` (probe → "Time to ask", end → "Session complete" — both `focused` in the
  a11y tree).
- **Tap targets (patient kiosk):** all five buttons ≥ 199×64 px — comfortably above the 48px
  web.dev minimum.
- **Forms:** login email input and session-notes textarea both properly labelled; no orphaned
  inputs found.
- **Contrast:** no Chrome low-contrast issues reported; palette on /progress was validated by the
  chart's own palette check (4.55:1 on white).

## Fix made in this pass

The chart's describable summary had one wellness-copy edge: when the latest session ended lower
than the first (e.g. a session ended immediately at the guaranteed 0 s win), it read "…went from
34 sec to 0 sec" — technically accurate, emotionally a collapse. `PROGRESS_COPY.summary.moved`
now leads with the best delay reached and folds in the rebuild reassurance; the separate
rebuilding sentence is skipped in that branch to avoid repetition. Test updated to pin the new
framing and forbid `went from|down to`.
